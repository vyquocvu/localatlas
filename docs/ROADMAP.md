## Current implementation slice

Verified implementation: safe project relinking, managed project profile and append-only decision log (`project/profile.md`), task-scoped session/context flow (`sessions/<uuid>.md`), impact analysis and human-confirmed change proposals (`proposals/<uuid>.md`), evidence-backed project recap drafts (`recaps/<timestamp>.md`), cross-project portfolio health summary, role-based document templates, Git commit-to-task traceability, workspace/knowledge health audit, and project-scoped shell and agent (Codex, Claude Code, Qoder CLI) terminals. Task details now edit title, body/checklist, priority, epic, milestone, status, and dependency through a reviewed proposal that preserves Markdown frontmatter and content; roadmap UI can create and edit epics and milestones against actual project records with ETag preconditions. Task dependencies are normalized same-project task IDs; creation validates references, while changes to existing tasks require a proposal and explicit confirmation. Self-links, missing/cross-project IDs, cycles, stale confirmation targets, and cycles introduced after preview are rejected. Roadmap/board surfaces report legacy broken references; completed and cancelled dependencies count as resolved without automatic task status changes. The task workspace also provides project-local saved filters/sort orders and a priority-ranked “Ready to start” view that explains unresolved prerequisites without claiming or changing tasks. The selected agent CLI (Codex, Claude Code, or Qoder) launches with bounded project/task/document context; the shared CLI resolves managed workspace directories and the server watcher invalidates UI state after external CLI changes. All workspace records remain canonical Markdown under `LOCALATLAS_HOME`; imported repositories remain strictly read-only to LocalAtlas project-management operations. Task context follows direct dependencies and explicit links from those task documents, with bounded excerpts.

Git traceability distinguishes task IDs in commit subjects from session-start HEAD snapshots; the Git Activity UI can search bounded history by time window and commit cap, and reports searched scope/truncation while treating Git timeout or missing Git as unavailable evidence. Portfolio summary work is bounded to four projects at a time, reuses one path snapshot for task/proposal/session reads, and reports per-project stale data instead of failing the whole overview. Health analysis reuses its reconciled index for backlink checks. The portfolio attention inbox gathers blocked/critical tasks, pending proposals, paused sessions, and broken links with source paths and evidence timestamps; orphan notes stay informational, health scores are labeled heuristic, and project status filters include paused/archived. Synthetic benchmarks and environment-specific results are recorded in [performance benchmarks](PERFORMANCE_BENCHMARKS.md); rerun with `npm run benchmark:portfolio`.

- [x] Add a desktop packaging release-gate workflow (`.github/workflows/desktop-package.yml`, macOS runner, on `v*` tags and `workflow_dispatch`) with explicit `bundle.targets` (`app`, `dmg`): it runs `tauri:build`, asserts the `.app`/`.dmg` exist, records ad-hoc `codesign` info, verifies the DMG checksum, and uploads the bundle. Guarded by test `LA-M6-04`. (2026-10-30)
- [ ] Build an installable desktop bundle and smoke-test installation, first launch, backend shutdown, and restart on a clean supported machine. Verify CLI/web workflows against the same workspace and test backup/restore across an upgrade before marking desktop conversion complete.
